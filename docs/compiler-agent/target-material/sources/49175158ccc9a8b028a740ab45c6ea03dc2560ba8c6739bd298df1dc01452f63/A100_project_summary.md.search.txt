# A100 项目知识摘要

本项目只让 K3 A100 执行生成的计算代码。多核支持和适用矩阵算子的 IME 路径均为必需；单核是调试与对照配置。系统和 workflow 可以运行在其他核心。

## 必须带入实现的事实

| 项目 | 已读资料的结论 | 实现影响 |
|---|---|---|
| 向量能力 | A100 VLEN=1024，RVV 1.0 | 根据实际宽度处理向量布局与尾块 |
| 普通矩阵 | INT4 8×32×8；INT8 8×16×8；FP16/BF16 8×8×8，浮点累加 FP32 | 布局和 lowering 必须区分指令族 |
| 寄存器 | 当前矩阵实现 LMUL=1；目的与输入不重叠；双寄存器目的偶数对齐 | 约束贯穿指令选择与分配 |
| 隐式状态 | v0/v1 的稀疏/缩放用途与 MCPM 浮点格式选择 | 显式跟踪隐式操作数和控制状态 |
| 多核资源 | Preview 描述矩阵引擎由两个计算核心共享 | 不把八个工作线程当成八份独立矩阵吞吐；上板确认配对 |
| 本地存储 | 手册标注每 cluster 1.5 MB scratchpad | 不能误当成每线程私有容量；可用量和分配接口待测 |
| 标称性能 | 60 TOPS 限定 INT4 sparse | 不能直接用于浮点或普通稠密算子目标 |
| 软件示例 | 官方推理示例用 8–15 核心编号与显式资源分配 | 只是示例，必须探测实际允许集合 |

每项精确引用、版本和 Fact ID 见同目录 `PROJECT_STATE.json` 与自动生成的事实 Markdown。归档不等于逐页审阅：本次提炼重点为 CPU 手册 A100 章节、矩阵规范第 1–2 章和编码约束、官方并行推理章节，以及 Preview 共享计算章节。其他章节可搜索后按需阅读。中文/英文同一规范都已归档。遇到冲突同时保留来源并解析适用范围。

## 多核实现要求

使用持久工作线程池；任务数和线程数独立；只在实测识别的 A100 集合放置工作线程。矩阵乘优先分配互不重叠的输出 tile；共享输入打包须明确生产、可见、读取和释放时机。跨线程归约需要显式合并，遵守输入比较策略。记录每个工作线程完成的单位、观察到的核心以及实际工作区间，不能以创建线程数替代并行证据。

线程数、输出分块、寄存器分块、打包布局及共享引擎放置应联合调优。保留 1/2/4/8 工作者的可配置路径；实际 sweep 只使用当前允许集合支持的配置。小问题允许选择少量工作线程，但完整交付必须在足够大的代表性算子上证明多核实际工作。不能把独立测试用例并发执行当作生成代码并行。

## 矩阵路径要求

矩阵指令必须出现在选中并执行的变体里。保存最终反汇编或指令清单、产物校验值、运行日志和参考比较结果。普通向量/标量路径覆盖不适合矩阵指令的操作、形状和尾块。矩阵指令清单中的静态出现不能单独证明动态执行；需要归因时增加执行轨迹或采样。

打包、线程调度、同步和搬运计入端到端耗时，并另报阶段耗时。预打包复用必须在双方使用同一复用假设时比较。不能把生成了矩阵指令当成获得了性能提升。整数、索引和布尔精确；浮点误差上限完全来自算子输入，不从硬件峰值或优化目标反推。

## 仍需验证

尚未选择算子语料，也没有目标硬件执行入口。本机没有执行 A100 指令。核心编号、线程启用、共享引擎配对、TCM/DMA 软件接口、已安装工具链和实测带宽均未被确认，已存为 Assumption。不得自动清理其他进程的资源或照抄旧平台编号。

## Conditional design guidance

- 前提：存在足够多互不重叠的输出块。收益：简化同步并支持多核。成本：不均衡和共享资源争用需要实测。采用后必须形成 Decision。
- 前提：打包成本能由计算量或权重复用摊薄。收益：利用矩阵扩展。成本：额外存储、打包和尾块处理。比较普通路径与矩阵路径的完整耗时。
- 前提：已验证本地存储和搬运接口及可见性。收益：复用与重叠。成本：容量、同步、资源占用。不能在这些事实缺失时假定 TCM/DMA 可用。
